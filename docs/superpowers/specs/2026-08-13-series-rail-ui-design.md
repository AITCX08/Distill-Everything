# 作品轨道界面优化设计

## 背景

工作台中的“作品轨道”已经具备逐集选择和状态表达能力，但新版主题样式表没有包含 `series-rail` 组件样式，浏览器因此使用原生按钮外观，将第 1 至第 8 集显示为连续的灰色数字条。该呈现方式与现有深色科技风设计不一致，也无法清晰表达完成、执行、失败和等待状态。

## 目标

- 将连续数字条改为清晰、紧凑的节点式作品轨道。
- 保留现有逐集点击能力和状态计算逻辑，不改变任务数据与后端接口。
- 让用户无需查看执行队列表格，也能快速识别每集状态和当前选择。
- 保持键盘操作、焦点提示和读屏语义完整。
- 兼容桌面端、窄屏和较长系列。

## 视觉方案

采用“圆形节点轨道”方案，并继续使用项目现有 Fluent UI、深色表面和青色品牌强调色。

### 容器

- 作品轨道作为独立信息区显示在任务概览下方。
- 标题行左侧显示“作品轨道”，右侧显示总集数。
- 节点区域使用深色半透明背景、细边框和统一圆角，与任务概览卡片保持一致。

### 节点

- 每集使用最小 `40 × 40px` 的圆形按钮，满足触控和键盘操作需要。
- 节点之间使用一条低对比度连接线，表达系列顺序。
- 数字使用等宽字体并保持居中；状态图标不能取代集数，避免用户失去位置判断。
- 连接线属于纯视觉元素，不进入无障碍树。

### 状态

| 状态 | 视觉表现 |
| --- | --- |
| 已完成 | 青绿色描边、轻微绿色底色，并显示小型完成标记 |
| 执行中 | 青色高亮描边和柔和外发光 |
| 失败 | 红色描边、低透明红色底色和警示标记 |
| 等待处理 | 深色背景、弱化边框和次要文字颜色 |
| 当前选中 | 在原状态外增加双层焦点环，不覆盖状态色 |

### 交互

- 点击节点继续调用现有 `onSelect(rowId)`，打开对应作品详情。
- 悬停时显示浏览器提示文本：“第 N 集 · 状态”。
- `aria-label` 保持“第 N 集，状态”，`aria-pressed` 表示当前选择。
- 键盘焦点使用清晰的青色外轮廓；焦点与选中状态可以同时识别。
- 只使用颜色以外的文字或标记辅助表达完成与失败状态。

## 响应式规则

- 桌面端优先单行展示，节点保持固定尺寸，不压缩为小按钮。
- 节点较多或可用宽度不足时自动换行；每行保持一致间距。
- 换行后不绘制跨行连接线，避免产生错误的视觉路径。
- 小于 `560px` 时缩小横向间距，但节点触控尺寸不低于 `40px`。

## 代码范围

- 更新 `dashboard/src/features/mission-control/SeriesRail.tsx`，补充状态标记和提示文本所需的语义结构。
- 更新 `dashboard/src/theme/operations.css`，新增完整的 `series-rail` 样式与响应式规则。
- 更新 `dashboard/src/features/mission-control/SeriesRail.test.tsx`，验证状态、选中语义、点击和可访问名称。
- 如视觉验收需要，可补充现有工作台端到端用例，但不修改后端接口、任务状态模型或任务排序算法。

## 验收标准

1. 第 1 至第 8 集不再显示为浏览器原生灰色按钮条。
2. 每集显示为独立圆形节点，并能识别已完成、执行中、失败和等待状态。
3. 当前选择具有明确但不过度的双层高亮。
4. 点击任一节点仍能选择对应作品。
5. 键盘焦点可见，读屏名称包含集数与状态。
6. 在桌面宽度、平板宽度和手机宽度下均无横向溢出；空间不足时自然换行。
7. 前端定向测试、构建检查和本地浏览器视觉验收通过。

## 非目标

- 不调整作品状态的后端计算逻辑。
- 不改变执行队列表格、任务概览或详情抽屉的信息架构。
- 不增加动画库或新的组件依赖。
- 不在本次修改中处理小红书平台适配功能。
