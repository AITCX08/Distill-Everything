# Dashboard 自定义模型设置设计

## 1. 目标

在左侧“运行状态”卡片中增加模型设置入口，让用户无需编辑 `.env` 或重启 Dashboard，即可调整后续任务使用的转写模型与摘要模型。

首版支持：

- 修改 FunASR 转写模型名称；
- 在已支持的摘要服务商中切换服务商；
- 输入自定义摘要模型名称，例如 `deepseek-v4-flash`；
- 保存后立即刷新侧栏显示；
- 恢复为环境变量提供的默认配置。

首版不支持在网页中查看或修改 API Key、API 地址等敏感信息。

## 2. 用户界面

### 2.1 设置入口

“运行状态”卡片标题行右侧增加一个齿轮图标按钮，按钮的无障碍名称为“设置模型”。按钮保持现有深色科技风，不新增侧栏菜单项。

### 2.2 设置弹窗

点击按钮后打开 Fluent UI 对话框，包含：

1. 转写模型
   - 服务商固定显示为 `FunASR`；
   - 模型名称为可编辑文本框，当前值例如 `paraformer-zh`。
2. 摘要模型
   - 服务商为下拉选择：Anthropic、OpenAI、Qwen、DeepSeek、Ollama；
   - 模型名称为可编辑文本框，允许输入受支持格式的自定义模型标识。
3. 生效说明
   - “保存后对新启动、恢复或重试的任务生效；已经运行的任务不会中途切换模型。”
4. 操作
   - “保存设置”；
   - “恢复环境默认配置”，点击后需在确认对话框中再次确认；
   - “取消”。

保存成功后关闭弹窗并立即更新侧栏模型状态。保存失败时弹窗保持打开，在相应字段或操作区显示中文错误，不丢失用户输入。

## 3. 配置来源与优先级

模型配置按以下优先级计算，靠前者优先：

1. `data/dashboard-settings.json` 中的用户覆盖值；
2. `.env` 或系统环境变量；
3. 项目内置默认值。

“恢复环境默认配置”只删除模型覆盖字段，不修改 `.env`，也不删除默认保存路径等其他设置。

## 4. 本地设置存储

复用 `data/dashboard-settings.json`，扩展后的示例结构：

```json
{
  "default_directory": "C:\\Users\\Example\\Documents\\Distill",
  "models": {
    "transcription": {
      "model": "paraformer-zh"
    },
    "summary": {
      "provider": "deepseek",
      "model": "deepseek-v4-flash"
    }
  }
}
```

新增一个共享的本地设置存储组件，负责：

- 读取完整 JSON 对象；
- 合并指定字段，而不是覆盖整个文件；
- 通过临时文件和 `os.replace` 原子写入；
- 使用进程内锁避免保存路径和模型设置同时写入时互相覆盖；
- 保留未知字段，便于后续扩展。

现有 `OutputDirectoryService` 改为通过该组件更新 `default_directory`，解决当前写入时覆盖其他设置字段的问题。

## 5. 后端接口

### 5.1 读取模型设置

`GET /api/v1/settings/models`

返回当前有效配置与是否存在用户覆盖：

```json
{
  "transcription": {"provider": "FunASR", "model": "paraformer-zh"},
  "summary": {"provider": "DeepSeek", "provider_id": "deepseek", "model": "deepseek-chat"},
  "overridden": false
}
```

接口不得返回 API Key、API 地址、Cookie 或其他凭据。

### 5.2 保存模型设置

`PUT /api/v1/settings/models`

请求示例：

```json
{
  "transcription_model": "paraformer-zh",
  "summary_provider": "deepseek",
  "summary_model": "deepseek-v4-flash"
}
```

保存成功后返回新的有效配置。接口沿用 Dashboard 现有的本地会话与 CSRF 防护。

### 5.3 恢复默认配置

`DELETE /api/v1/settings/models`

删除本地模型覆盖并返回由环境变量或项目默认值计算出的有效配置。该接口同样要求本地会话与 CSRF 防护。

## 6. 校验规则

- 摘要服务商必须属于项目已支持的服务商集合；
- 模型名称去除首尾空格后长度为 1 至 128 个字符；
- 模型名称只接受字母、数字、点、下划线、冒号、斜杠和连字符；
- 禁止换行、控制字符和路径遍历片段；
- 校验失败返回 HTTP 422 和可供前端翻译为中文提示的稳定错误码；
- 不通过网络探测模型是否真实存在，避免保存设置时引入外部请求和供应商耦合。

例如 `deepseek-v4-flash` 可通过格式校验，但是否可由当前 API 账户调用，将在实际任务请求时由供应商返回结果。

## 7. 生效机制

### 7.1 Dashboard 主进程

保存成功后，将有效设置同步到 `SourceDistillationRunner.config`，使随后由主进程创建的新任务使用新配置。健康接口不再读取启动时缓存的模型快照，而是读取当前有效配置。

### 7.2 独立任务子进程

任务子进程启动时调用 `load_config()`。`load_config()` 在读取环境变量后加载同一份本地模型覆盖，因此保存后启动、恢复或重试的子进程会使用新模型。

已经运行的子进程持有自己的配置对象，不进行热切换。这保证同一条流水线不会在转写、清洗或摘要中途改变模型。

## 8. 错误处理

- 设置文件不存在：按环境配置运行；
- 设置文件无法解析：保留原文件，接口返回明确错误，不静默覆盖；
- 原子写入失败：返回保存失败，内存配置保持原值；
- Dashboard 主进程同步失败：不报告保存成功；
- 实际模型调用失败：由任务流水线按现有错误和重试机制处理，设置页面不伪装为连接测试。

## 9. 跨平台要求

- 使用 `pathlib.Path`、UTF-8 JSON 和 `os.replace`；
- 不调用 CMD、PowerShell、Shell 或平台专属脚本；
- Windows 与 macOS 使用相同的设置文件结构和 API；
- 不启动额外终端窗口或浏览器窗口。

## 10. 测试与验收

### 10.1 后端

- 设置存储进行合并写入且保留默认保存路径；
- 原子写入后可由新的 `load_config()` 实例读取；
- GET、PUT、DELETE 接口返回正确的有效配置；
- 非法服务商和非法模型名称返回 422；
- 响应中不包含 API Key 和 API 地址；
- 保存后主进程配置同步，运行中任务对象不被修改。

### 10.2 前端

- 齿轮按钮位于“运行状态”标题行；
- 弹窗正确显示当前转写与摘要模型；
- 可输入自定义模型名称并保存；
- 保存后侧栏无需刷新即可更新；
- 恢复默认配置需要二次确认并正确更新；
- 后端错误以中文显示，输入内容保留；
- 键盘可完整操作弹窗，焦点关闭后返回设置按钮。

### 10.3 浏览器验收

- 在桌面宽度下，设置入口不会挤压模型名称；
- 在窄屏布局下，沿用当前策略隐藏整个运行状态卡，不额外暴露悬浮按钮；
- 保存 `deepseek-v4-flash` 后，侧栏摘要模型显示为 `DeepSeek / deepseek-v4-flash`；
- Dashboard 重启后仍显示保存值；
- 恢复默认配置后显示环境变量对应的模型。

## 11. 范围外事项

- API Key、API Base URL 的网页配置；
- 从供应商在线拉取模型列表；
- 在保存时发起计费或连通性测试；
- 对正在运行的流水线热切换模型；
- 为单个任务单独选择模型。
