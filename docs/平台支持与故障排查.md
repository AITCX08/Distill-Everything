# 平台支持与故障排查

## 支持矩阵

| 能力 | Windows | macOS | 说明 |
| --- | --- | --- | --- |
| CLI 与本地 Dashboard | 正式支持 | 正式文档支持、基础 CI 覆盖 | Dashboard 只监听 `127.0.0.1`。 |
| Dashboard 启动 | 使用隐藏启动方式 | 使用前台 `python main.py dashboard --port 8765 --no-open` | 不要将服务暴露到局域网或公网。 |
| Python 基础回归 | 正式支持 | macOS CI 离线基础用例 | macOS CI 不下载媒体、不调用外部模型。 |
| Bilibili / 抖音扫码 | 需在本机设备验收 | 需要设备验收 | 登录凭据不会返回到 Dashboard、SSE 或日志。 |
| YouTube（yt-dlp） | 实验性支持 | 实验性支持 | 公开内容无需登录；不处理会员、付费或需登录的视频。 |
| Playwright 浏览器 | 已在 Windows 工作流使用 | 需要设备验收 | 安装 Chromium 后再执行真实平台操作。 |
| FunASR Apple Silicon MPS | 不适用 | 需要设备验收 | 未承诺与 CUDA/CPU 相同的稳定性或性能。 |

## Bilibili 直接视频链接

Bilibili 适配器会在现有蒸馏流水线内直接解析以下输入，不会为链接解析启动浏览器：

- `https://b23.tv/...` 短链接；
- `https://www.bilibili.com/video/BV...`、`https://www.bilibili.com/video/av...`；
- 裸 `BV...` 或 `av...` 标识。

短链接只允许在 `b23.tv`、`bilibili.com` 白名单主机之间进行最多 4 次 HTTP 重定向，随后调用 Bilibili 视频元数据接口得到标题、时长、封面和 BV 号。解析后的单个视频会继续复用原有下载、音频、转写、清洗、摘要和产物输出阶段；下载仍遵循当前 Bilibili 凭据策略。

如果输入不是上述格式、重定向主机不在白名单、重定向次数超限，或元数据接口返回错误，任务会在预检阶段明确失败，不会退回到浏览器兜底。Bilibili 扫码登录仍需要浏览器，这是认证流程而不是视频链接解析流程。

“正式文档支持”表示安装、启动、排障与 CI 基础路径已维护；并不表示所有第三方平台、扫码流程、浏览器自动化和硬件加速都已经在真实 macOS 设备上完成验收。

## YouTube（yt-dlp）

YouTube 适配器复用已有的 `yt-dlp` 依赖，不启动浏览器、不需要登录，支持：

- `https://www.youtube.com/@handle`
- `https://www.youtube.com/channel/UC...`、`/c/...`、`/user/...`
- `https://www.youtube.com/watch?v=...` 或 `https://youtu.be/...`（单视频）

枚举使用 `yt-dlp --flat-playlist --dump-json --playlist-end 200`，下载使用 `-x --audio-format wav`。常见故障：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `yt-dlp is not installed` | 依赖未安装 | `pip install -r requirements.txt` |
| `yt-dlp failed: ...` | 视频受限、地区限制或需要登录 | 换成公开视频；本项目不支持携带 Cookie 登录 YouTube |
| 枚举结果为空 | 频道无公开视频或链接写错 | 用浏览器确认频道页可访问 |
| 下载很慢 | yt-dlp 未使用 aria2c 等外部下载器 | 属预期行为；单视频串行下载 |

YouTube 是实验性支持：CI 只用桩数据覆盖解析与映射，不做真实网络下载。

## 扫码登录（Dashboard 页内弹窗）

Dashboard 的「平台与登录」对**所有需要登录的平台**都用同一个页内弹窗：

| 平台 | 二维码来源 | 前提 |
| --- | --- | --- |
| Bilibili | 后端调用官方扫码接口生成 PNG，浏览器只拿到图片 | 无 |
| 抖音 | 后端用**无头**持久浏览器打开抖音登录页，截取二维码元素 | `playwright install chromium` + 能访问抖音 |

流程：点「登录 <平台>」→ 弹窗出现二维码 → 手机扫码 → 弹窗状态自动从「等待扫码」变成「登录成功」，平台卡片同步刷新。二维码只在本地接口 `GET /api/v1/platforms/<platform>/login/<op>/qr` 上存在，不写入页面存储或日志。

抖音特殊处理：拿不到二维码（Chromium 缺失、页面结构变化）时，弹窗会给出明确原因并提示改用 CLI：

```bash
python main.py source login douyin   # 外部可见浏览器，稳定兜底
```

CLI 的 `source login` 仍保留外部浏览器模式，适用于服务器/无 Dashboard 的场景。

## 抖音收藏夹 / 合集

抖音的「收藏」不是按创作者组织的，因此它被建模成独立的 target 类型 `collection`，与创作者、单视频并列：

```bash
# 我的收藏（需要先登录，页面会停在 showTab=collect）
python main.py source creator "https://www.douyin.com/user/self?showTab=collect" --dry-run

# 某个合集 / 收藏夹页面
python main.py source creator "https://www.douyin.com/collection/7123" --dry-run

# 脚本里不想带 URL 时
python main.py source creator "douyin:collection:7123" --platform douyin --dry-run

# 登录后正式蒸馏（输出到 output/self-collect-douyin-self-collect/ 之类）
python main.py source creator "https://www.douyin.com/user/self?showTab=collect" --platform douyin
```

实现要点：

- 解析在浏览器之外完成（`extract_collection_target`），不会因为解析一个收藏夹就拉起 Chromium；
- 枚举复用浏览器产生的 JSON 响应，但**只接受收藏类端点**（`listcollection` / `favorite` / `mix`），不含 `/aweme/post/`——否则主页作品流会混进收藏夹；
- 端点路径随抖音版本变化，抓不到时抛 `PlatformEnumerationError` 并列出期望的路径，不会静默返回空。

已知限制：需要 `playwright install chromium` 与有效登录；收藏夹接口属于抖音内部接口，版本升级后可能失效，届时按报错里的路径更新 `src/platforms/douyin/enumerator.py::_COLLECTION_API_MARKERS`。

## 自动识别平台

不给 `--platform` 时默认 `auto`，由 `PlatformRegistry.detect()` 依次调用各适配器的 `matches()`：

```bash
python main.py source creator "https://www.youtube.com/@handle"
python main.py source creator "https://space.bilibili.com/12345678"
python main.py source creator "https://www.douyin.com/user/SEC_UID"
```

链接同时匹配多个适配器会报 `AmbiguousPlatformError`；都不匹配会报 `PlatformNotDetectedError` 并提示可用平台。新增平台只需要实现 `PlatformAdapter` 并注册进 `main.build_platform_manager`，CLI 与 Dashboard 会自动列出。

## 安装与依赖检查

在 macOS 的 zsh 中：

```zsh
python3 --version
brew --version
brew install ffmpeg
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m playwright install chromium
```

开发 Dashboard 时还需要 Node.js 24：

```zsh
node --version
cd dashboard
npm ci
```

若 `ffmpeg` 或 Node 不在 `PATH` 中，先修正 shell 配置后重新打开终端，再继续安装。不要将系统路径、浏览器 profile、Cookie 或 `.env` 内容粘贴到公开 issue。

## 启动与健康检查

macOS 使用前台进程启动，方便在终端中观察错误：

```zsh
python main.py dashboard --port 8765 --no-open
```

另开一个终端确认服务：

```zsh
curl http://127.0.0.1:8765/api/v1/health
```

响应中的 `status` 应为 `ok`，`static_compatible` 应为 `true`。浏览器访问 `http://127.0.0.1:8765/` 即可打开界面。

Windows 的隐藏启动与后台测试规则只适用于其专用说明；macOS 不需要也不应使用这些 Windows 专用机制。

## 常见问题

### 端口 8765 已被占用

可改用其他未占用端口，例如：

```zsh
python main.py dashboard --port 9000 --no-open
```

然后访问对应的本地地址。若需要定位占用进程，只记录进程名称和端口；不要在公开渠道提交完整终端历史。

### Playwright 或 Chromium 安装失败

先确保虚拟环境已激活，再重新执行 `python -m playwright install chromium`。公司网络、代理配置或系统安全策略都可能阻止浏览器下载。安装成功不等于 Bilibili 或抖音扫码流程已完成设备验收。

### Finder 或 Explorer 没有打开产物目录

Dashboard 只能打开当前任务已经授权的本地保存位置。确认任务已完成、产物存在，并检查系统是否阻止应用打开文件管理器。不要尝试把保存目录改为网络共享或公开可访问的位置。

### macOS 上的真实扫码或 Apple Silicon ASR

这两类流程需要实际设备验收。遇到问题时，请提供版本号、macOS 版本、芯片类型、脱敏后的错误摘要和可复现步骤；不要提供二维码、Cookie、浏览器 profile、API Key、媒体文件或完整 Worker 日志。

## 提交脱敏问题报告

问题报告至少应包含：项目版本或提交号、操作系统版本、Python/Node 版本、最短复现步骤、预期行为、实际行为和脱敏错误摘要。请先阅读 [SECURITY.md](../SECURITY.md)；安全问题不要公开提交。

## 抖音页内扫码失败（已修复）

抖音对 headless 浏览器直接返回「验证码中间页」，DOM 里没有登录入口，因此页内抓不到二维码。
现在的登录流程：

1. 用**有头**上下文打开 `douyin.com`（窗口移到屏幕外，不打断操作）；
2. 点顶部「登录」，再自动切到面板里的「扫码登录」页签；
3. 取面板内**面积最大**的 `data:image` 图片并校验尺寸 ≥100px（面板还有 22×22 的刷新图标）。

如果仍然失败，通常是风控升级：改用终端 `python main.py source login douyin` 手动扫码。

## 抖音登录的资源占用（已优化）

登录流程现在是：**headless + 反检测参数**，屏幕外不弹窗；二维码抓取后释放重页面渲染进程。

| 阶段 | 私有内存 | 说明 |
| --- | --- | --- |
| 页面加载峰值 | ~750 MB | 首页信息流会拉起渲染进程，持续约 20 秒 |
| 等待扫码（常态） | **~200 MB** | 关闭重页面并终止其渲染进程，只保留空白页 |
| 登录完成/超时 | 0 | 浏览器进程退出 |

关键参数在 `src/platforms/douyin/session.py::_LAUNCH_ARGS`：
`--disable-blink-features=AutomationControlled`、固定 UA/`--lang=zh-CN`（不加会被拦到验证码中间页），
`--disable-gpu*`、`--renderer-process-limit=1`、`--js-flags=--max-old-space-size=256`（控资源）。

同一时刻只允许一个抖音浏览器：协调器串行化 + `douyin-profile` 文件租约，CLI 与 Dashboard 并发会直接报占用。
